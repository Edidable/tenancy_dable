A message the gem adds to `errors` is a KEY, never a literal string: `errors.add(attr, :cross_tenant)`, `errors.add(:role, :last_owner)`, `message: :slug_format`. A new message adds its key to BOTH `en.yml` and `pt-BR.yml` under `errors.messages`, a rendering example in `spec/i18n/messages_spec.rb`, and a host-override example.
Keep the keys under `errors.messages` (the last entry of Active Model's lookup chain), never `activerecord.errors.messages`, which would shadow a host's `errors.messages` override.
`en` always loads; `pt-BR` loads only when `config.i18n.default_locale` or `available_locales` declares it (symbol or string), chosen by `Railtie.locale_files`. A locale file added to the gem is not loaded for everyone by default: it would join every host's `I18n.available_locales`.
The `pt-BR` declaration is read when the railtie's initializer runs: it must be in `config/application.rb` or `config/environments/*.rb`, never only in `config/initializers`.
The gem's files are PREPENDED to `I18n.load_path` (`Railtie.prepend_load_path`, which moves them if present), so any host file wins; never append, never add them to `app.config.i18n.load_path`.
`CrossTenantError::MESSAGE` must equal the `en` `cross_tenant` text; change both together (`spec/i18n/messages_spec.rb` and `spec/contract_spec.rb` lock it).
`errors.details` carries the key (`:cross_tenant`, `:last_owner`) and `:invalid` for the slug format; do not switch a detail back to the English string.
Exception messages stay English; only validation messages are keys.
Proof: `spec/i18n/messages_spec.rb` (rendering, overrides, load order, details), `spec/i18n/locale_files_spec.rb` (conditional `pt-BR`).
Narrative: docs/domains/i18n.md
