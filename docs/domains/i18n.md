# I18n: the gem's validation messages

Every validation message the gem adds to a record's `errors` is an error key with a shipped default, not a literal English string. A host overrides a message the way it overrides any Active Model message, in its own locale files, and `errors.details` carries the key rather than the English text. Exception messages (the text of a raised `TenancyDable::Error`) stay English and are outside this domain.

## The keys and where they are used

The defaults live in [FILE:lib/tenancy_dable/locale/en.yml] and [FILE:lib/tenancy_dable/locale/pt-BR.yml], under [NAMESPACE:errors.messages]. The YAML files are the source of truth for the keys:

- [KEY:cross_tenant] is added by the cross-tenant `belongs_to` validation in [FILE:lib/tenancy_dable/scoped.rb] with `errors.add(reflection.name, :cross_tenant)`.
- [KEY:last_owner] is added by the last-owner guard in [FILE:lib/tenancy_dable/models/membership_model.rb] with `errors.add(:role, :last_owner)`.
- [KEY:slug_format] is the message of the slug format validation in [FILE:lib/tenancy_dable/models/tenant_model.rb], written `format: {with: SLUG_FORMAT, message: :slug_format}`; the error type stays `:invalid`.

The create refusal for a foreign tenant raises, so it adds no message and has no key. [SPEC:spec/i18n/messages_spec.rb] renders each key in `en` and in `pt-BR`, and [SPEC:spec/contract_spec.rb] ("ships the :en and :pt-BR locales on I18n.load_path with the :en default equal to MESSAGE") locks that both files are loaded in the harness and that the Portuguese `cross_tenant` text is the shipped one.

## Why `errors.messages`

The key namespace is [NAMESPACE:errors.messages] and not `activerecord.errors.messages`. Active Model's lookup chain tries, from most to least specific, `activerecord.errors.models.<model>.attributes.<attribute>.<key>`, `activerecord.errors.models.<model>.<key>`, `activerecord.errors.messages.<key>`, `errors.attributes.<attribute>.<key>`, and last `errors.messages.<key>`. Defaults at the last entry are shadowed by every host override; defaults under `activerecord.errors.messages` would shadow a host's `errors.messages` override. [SPEC:spec/i18n/messages_spec.rb] ("host overrides") proves an override wins at the model-attribute level for `cross_tenant`, and at `errors.messages` for `last_owner` and `slug_format`.

## Locales: `en` always, `pt-BR` only when declared

`en` is always loaded. `pt-BR` is loaded only when the host declares it, in [CONFIG:config.i18n.default_locale] or in [CONFIG:config.i18n.available_locales], as a symbol or a string. The selection is the class method [METHOD:TenancyDable::Railtie.locale_files], which takes the host's `config.i18n` and returns the file paths. [SPEC:spec/i18n/locale_files_spec.rb] proves the cases: an English-only host gets `en.yml`; a host with `default_locale` or `available_locales` containing `pt-BR` gets both; string and symbol forms both count; every returned file exists.

The reason `pt-BR` is conditional is that loading a locale file adds its locale to `I18n.available_locales`. Loading `pt-BR.yml` unconditionally would add `pt-BR` to every host, including English-only ones. A `pt-BR` host, in turn, sees Portuguese defaults instead of Rails' translation-missing text. Any other locale is the host's to add: a host whose locale is neither `en` nor `pt-BR` must translate the gem's keys, or enable fallbacks that reach `:en` (`config.i18n.fallbacks = [:en]`; plain `fallbacks = true` falls back to the host's default locale, which is not `en` for such a host), or Rails renders its translation-missing text.

The declaration is read when the railtie's initializer runs, so it must be in `config/application.rb` or in `config/environments/*.rb`. A setting made only in `config/initializers/*.rb` runs after the railtie's initializers and is not seen. See the gotcha below.

## The load path: the gem's files go first, so host files win

The railtie's initializer [INITIALIZER:tenancy_dable.i18n] in [FILE:lib/tenancy_dable/railtie.rb] computes the files from `app.config.i18n` and, inside `ActiveSupport.on_load(:i18n)`, calls [METHOD:TenancyDable::Railtie.prepend_load_path], which sets `I18n.load_path = files + (I18n.load_path - files)`. A later file wins in I18n, so the gem's files placed first lose to every host file for the same key, however the host registered it. `config/locales` and `config.i18n.load_path` are added by `I18n::Railtie.initialize_i18n` after this hook, and a direct append to `I18n.load_path` in the application class body is already in the list; a plain append by the gem would have landed after that and won. The move also removes any earlier copy, so the gem's files appear once.

[SPEC:spec/i18n/messages_spec.rb] proves it two ways: "puts the gem's locale files before the host's, so a host file wins" checks the index order against the harness's own host locale file and that the host file loaded, and "moves the gem's files ahead of a host file appended earlier, so the host still wins" calls `prepend_load_path` against a list where the host file came first and asserts the gem's files lead and appear once.

## `CrossTenantError::MESSAGE` stays equal to the `en` default

[CONSTANT:TenancyDable::CrossTenantError::MESSAGE] is `"belongs to a different tenant"`. It is a compatibility constant, equal to the `en` default of `errors.messages.cross_tenant`; code that compared an error string to it keeps working in `en`, and `errors.added?(:parent, CrossTenantError::MESSAGE)` still matches. [SPEC:spec/i18n/messages_spec.rb] ("keeps CrossTenantError::MESSAGE equal to the :en default") and `spec/contract_spec.rb` lock the equality, so a change to the YAML text and the constant moves together or fails.

## `errors.details` carries symbols

`errors.details` for these errors carries the key and not the English string: `[{error: :cross_tenant}]` on the association, `[{error: :last_owner}]` on `:role`, and `:invalid` for the slug format, whose error type is `:invalid` and whose message is the key. [SPEC:spec/i18n/messages_spec.rb] ("errors.details") proves all three.

## Gotchas

### Gotcha: `pt-BR` declared too late

[SYMPTOM:a pt-BR host renders a `Translation missing` text in its validation errors, whose considered options end in `pt-BR.errors.messages.cross_tenant`]. [CAUSE:the host declared `pt-BR` only in `config/initializers/*.rb`, which runs after the railtie's `tenancy_dable.i18n` initializer has chosen the files, so only `en.yml` was loaded]. [FIX:declare `config.i18n.default_locale` or `config.i18n.available_locales` in `config/application.rb` or `config/environments/*.rb`, or add the gem's `pt-BR.yml` to the host's own load path]. [RULE:the locale declaration the gem reads is the one present when initializers run, so it belongs in application config and not in an initializer file]. [SPEC:spec/i18n/locale_files_spec.rb] proves the selection from a given config; no spec covers the initializer ordering itself.
